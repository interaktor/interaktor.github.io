#JavaScript #Study #WebDev

底层原理与JSON

主要讲一下这个todolist这个项目，它必定会使用的一个东西，那就是localStorage（本地存储），这个相当的重要，因为在todo list中你想要让我添加的列表，刷新之后，还要保存的话，那就必须要用到这个，这个东西表面上就是存储list的数据之类的，但是这个它没那么简单，总得来说就是页面有多少功能，它就会多少步骤，如果页面简单那保存数据也简单，步骤也不多，如果页面有超过5种功能以上那这个本地存储就有点难做，更多的是复杂。这个本地存储折磨了我三天之久，今天才来总结它的原理以及我遇到的坑点，我下面的讲解都是以ToDoList为模板来进行讲解localStorage它是怎么用的？具体步骤是什么？我会一一解答

1.JSON.stringify()它的作用是封包，因为localStorage只能识别文本内容，我们要存的东西一般都不是文本，而是数组之类的，所有要把我们的内容转化成localStorage可以认识的，也就是要用JSON.stringify(数据变量)，转化好的数据就可以让localStorage存储了

2.JSON.parse()它的作用和上一个相反，是用来解包，它是把封装成文本的数据，重新转化成它的原始状态，里面是填封装的变量

新增（Create）

首先来到新增，我来说一下原理，我们可以把本地存储和DOM分开来看一下，当我们点击了add_button之后，它会在页面上创建一个list(列表)，这个列表上面有两样数据，一个是content(内容)，另一个是none(状态)，我们本地存储要做的就是把刚创建好的list里面的con tent拿来存上，因为none(状态)，它不在add_button里面管理的，具体看代码

//声明一个变量叫todos，来存储页面上list的对应内容和状态
var todos;
//提前判断，因为后面localStorage会有很多数据，用户每次点击添加list后，我们都要检查一下，之后有过数据吗
if(localStorage.getItem('list')) { //检查有没有叫list这个名称的localStorage，名称要统一
		//如果有我们就把旧数据来装进去
		todos = JSON.parse(localStorage.getItem(todos)); //有旧数据肯定是封装过，需要解包
} else {
		//如果是第一次创建数据，我们就给这个todos空变量装一个「格式」也就是数组
		todos = []
}
//不管上面是有旧数据，还是第一次创建，它们能执行都是因为页面有创建新的list，它们才会触发
//所以在判断完之后，我们就装数据进去
//localStorage数据和DOM页面，它们每次创建位置是相同的，第一个页面list创建后，这个代码会把第一次list的内容给存到数组对象的第一个，以此类推，页面list的位置和数组对象里面的位置就是相同的
//push也就是放在数组的最后，后面创建的对象都会排到后面，和页面上的list相同
todos.push({text:input.value,completed:false});
//当我们把数据塞进localStorage之后，把这个修改的数组给打包封装起来
localStorage.setItem('list',JSON.stringify(todos));

上面的代码是在add_button之间添加的，也就是你页面有新的东西或者说有修改删除之类的，你的本地存储就要在对应的上面进行修改，功能越多，本地存储就要干的越多，上面的代码完成了页面有新内容，然后把页面这个内容它的数据给存入localStorage

初始化渲染

这个就是localStorage的核心部分了，原来的页面就是当我们刷新之后里面创建的DOM就会消失，初始化渲染就是让我们保存在localStorage里面的数据显示到页面上，每次刷新或者重新打开页面都会执行这个操作
此代码因为是页面进行/刷新时就会执行的代码，所以要放在「代码上方」

//首先判断本地存储有没有东西？如果有存数据在里面就执行，没有数据就不执行
//这里我们不用判断是文本还是数组，只要里面有数据就代表存了东西
if(localStorage.getItem('list')){
	//有数据我们就把数据拿出来，用一个临时变量来存这个数据
	var str = JSON.parse(localStorage.getItem('list'));
	//因为数组里面一般有多个对象，我们要用循环来执行每一个对象
	str.forEach(function(item,i){
		//这里面就和add_button里面的代码一样，因为我们现在只有数据，没法实例化到页面上，所以需要骨架
		//然后修改一下里面的一些代码部分
		 var li = document.createElement('li');
            li.classList.add('list');
            li.innerHTML = `<label>
                        <input class='list_checkbox' type="checkbox" ${str[i].completed ? 'checked':''}>
                        <span class='list_content'>${str[i].text}</span>
                        </label>
                        <button class='list_del'>del</button>`
            ul.appendChilden(li);
    //这里要考虑到判断，也就是checkbox它的状态是true还是false，因为这个input:checkbox它会影响到list和list_content它们的状态，就和ul点击事件是一样的，如果checkbox的状态是true那么list和list_content它们也要添加上相应的完成类名，不然在后继的数值统计的时候它无法找到这个已经为true的checkbox，所以数值统计不会把它们算上，特别注意
    //提前在innerHTML里面就判断checkbox它的状态，然后再到这里去判断list和list_content，因为上面的checkbox判断完后才能知道是true还是false，这个时候才好判断list的状态，当然list_content也可以在innerHTML里面判断，但是并不方便，这里可以一起给它们判断好
    var list_content = li.querySelector('.list_content') //因为页面上还没有list_content,所以不能用document
    if(str[i].completed) {
    	//如果checkbox它的状态为true，我们就让list 和 list_content加上相同的completed类名
    	li.classList.add('completed');
    	list_content.classList.add('list_completed');
    } else {
    	//如果checkbox它的状态为false，就把list 和 list_content的类名给去掉，这里的判断和ul里面是一样
    	li.classList.remove('completed');
    	list_content.classList.removde('list_completed');
    }
    //最后把这个li添加到页面上
    ul.appendChilden(li)
	})
	
	//注意一下在foreach循环中，每次循环都会给当前的变量创建一个独立的内存空间，10次循环就会开辟10个空间，它们不会互相影响，所		以不用担心重名和数据查找会不会找到一样的问题
}

删除数据

欢迎来到最后的删除，这里其实和修改completed是差不多的，只不过有一个细节需要注意，我们也需要获取所有的list和当前点击的list，但是删除的原代码是

if (e.target.classList.contains('list_del')) {
    ul.removeChild(e.target.parentNode);	
    //？它这里就会删除实体，那数据怎么删除？
    listConut();
    filters();
}

因为我们要检索所有的list，这里它已经把它删除了，我们点击检测的时候，也不可能找到这个已经被删除掉的list(列表)，所以很简单的方法就是把这个**ul.removeChild(e.target.parentNode);**给它排到最后删除，也就是我们先删除localStorage的数据，然后再删除DOM的实体

       			var data = JSON.parse(localStorage('list'));

       			//从index(点击的那一个)开始，删除一个，也就是开始那一个
