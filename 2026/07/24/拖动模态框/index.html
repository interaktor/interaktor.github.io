拖动模态框的BUG
2026-07-24 | JavaScript Study

在案例拖动的模态框里，我遇到了诸多问题

1.盒子距离最左侧的位置

「實際上它已經移動了，但是在觀感上它卻沒有移動」left改变物理排版，translatent只是视觉上的移动

(1)關於 transform:
translate(-50%, -50%) 造成的「數據與視覺脫節」BUG
現象：在計算 x = e.pageX - box.offsetLeft 時，算出來的 x 居然是個負數，但最終拖動效果卻完全正常。

(2)原因拆解：

JS 數據層：box.offsetLeft 只認 CSS 的 left: 50%，JS 認為盒子的左邊緣在屏幕中間。
CSS 視覺層：transform: translate(-50%) 只是顯卡渲染時的視覺位移（把盒子往左拉了半個身位），讓盒子的中心點在視覺上對齊了屏幕中間，但它完全不會更新 offsetLeft 的值。
負負得正：因為點擊時算出的 x 包含了這 250px 的視覺偏差（算出負數），而在拖動賦值 box.style.left 時，transform 又默默把盒子往左拉了 250px，兩者完美抵消！

(3)避坑結論：
如果要用 JS 精準計算拖動座標，建議移除 transform 居中，改用 JS 初始化算好居中位置，或者明確知道自己賦值的是「帶有視覺偏移的 left」。

2.移动要给谁？

这里我们需要移动模态框，但是我们要把mousemove给谁呢？

这里我们有两个选择，1.给box 2.给document

我们分别来测试一下这两个的区别

1.box

如果我们把move给到box的话，就会有一个问题，那就是当鼠标移动过快时，box就不会动了，也就是你移动的时候，鼠标必须在box范围内，不然移动是不起效果的，这样带来的体验是极差的，你只能慢慢的进行拖动，而且还会出来一些奇怪的BUG，当鼠标回到box，位置会发生重置

2.document

如果我们把move给到document，只要我们的鼠标是在文档内，那么它就可以一直移动，box也在文档内，如此鼠标再快也不会脱落box，因为鼠标一直都document里面

3.关于位置

(1)这里捋清楚一下，位置相关的事件

拿一个盒子来举例，这个盒子是w200px h200px 的一个盒子假设它在文档的最中间
文档的位置是 box.offsetLeft 可以得到盒子距离最左的位置
鼠标的位置是 e.pageX 可以得到鼠标距离最左的位置

(2)怎么得到鼠标距离盒子的位置呢

这里有一个公式是 鼠标距离盒子的最左距离 = 「鼠标距离最左的位置 - 盒子距离最左的位置」
得到鼠标距离盒子最左侧的位置后，我们就要移动时得到模态框的位置

(3)算出模态框的位置

模态框的位置 = 鼠标距离最左的位置 - 鼠标距离盒子最左的位置
这样算出来的结果就是我们模态框的最终位置，和上一个公式其实是相反的，上一个最后数值小，这个最后数值大
