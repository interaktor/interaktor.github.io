前言

许久没有更新Blog了，最近感冒加上学习Vue的过程大部分都没有很大的问题需要写，这次主要把组件通信相关的知识给过一下，梳理一遍，方便后继学习更高阶的课程，组件通信对我来说最容易错的是‘搞混’简单来说就是 组件的传输方式 和 是否为内置API 或 或第三方库，接下来就一个一个梳理组件通信的相关知识

组件通信只有两条轴：方向（谁给谁）和 方式（传值 / 通知 / 硬访问 / 共享）

方式 方向 一句话
props 父 → 子 父给子塞数据，子只读
自定义事件 emit 子 → 父 子通知父“发生了什么事”
v-model 父 ⇄ 子 props + emit 的组合糖，不是新东西
$attrs 父 → 子（透传） 隔代传递，中间那层不用管
$refs 父 → 子（硬访问） 父直接进入子组件内部，控制最强
$parent 子 → 父（硬访问） 子直接进入父组件内部
provide / inject 祖先 → 后代 跨层级，中间层完全无感
mitt 任意 → 任意 全局总线，谁都能发、谁都能收
Pinia 任意 ↔ 任意 不是“传”，是共享状态
默认插槽、具名插槽 父 → 子（结构） 父把 HTML 塞给子
作用域插槽 子 → 父（数据） 唯一一次“子把数据交给父”

01 props

props是组件通信里最常见和常用的，它的传输方向是 父组件 -> 子组件，也就是把父组件的数据传输给子组件使用

//父组件
<template>
	<!-- 这里注意:car是名称，car是数据，传过去要写对应的名称-->
	<Childe1 :car="car"/>
</template>
<script setup lang="ts">
 	import {ref} from 'vue'
  import Childe1 from '/Childe1.vue'
  	const car = ref('NSC')
</script>


//子组件
<template>
	<h1>{{ car }}</h1>
</template>
<script setup lang="ts">
  //defineProps是用于接收父传给子的数据「编译宏」，可以数组、对象、TS类型等写法
  //接收list + 限制类型
	//{}意思是它传进来可能不止一个数组对象，所以要用{}，
	//list代表子级只接收叫list的数据
	//这个数据它带:String的意思是规定这个list必须符合String字符串类型才行
	defineProps<{car:String}>()
</script>

父传函数给子调用，本质就是 emit 的底层原理，要理解，不要照做

02 自定义事件

自定义事件也就是emit，准确来说它是子通知父。子组件通过 emit 发出一个自定义事件，父组件通过 @事件名 监听，然后执行自己的方法。

<template>
  <h1>子组件</h1>
  <!--
    emit('事件名', 参数)
    - 第一个参数：自定义事件名称 send
    - 后面：要传给父组件的数据，可以多个
  -->
  <button @click="emit('send', msg.value)">
    点我向父组件发送数据
  </button>
</template>

<script setup lang="ts">
import { ref } from 'vue'

// 定义向外抛出的事件
// 语法：{ 事件名: [参数类型定义] }
const emit = defineEmits<{
  send: [data: string]
}>()

// 要传给父的数据
const msg = ref('LEGO')
</script>




<template>
  <h1>父组件</h1>
  <!--
    @send：监听子组件抛出的 send 事件（必须和 emit 第一个名字一致）
    "handleSend"：事件触发后执行的回调函数，名字自由起
    当子组件 emit('send', xxx)，xxx 就会作为参数传入 handleSend
  -->
  <Childe2 @send="handleSend" />
</template>

<script setup lang="ts">
import Childe2 from './Childe2.vue'

/**
 * 接收子组件传过来的数据
 * @param sonData 子组件发送过来的值
 */
function handleSend(sonData: string) {
  console.log('收到子组件传来的数据：', sonData)
}
</script>

总结一个就是，父组件用@accpet来监听事件，然后子组件过来emit(‘send’,date)来发送事件，最后就是父组件的send被触发，子组件就可以把数据发送给父组件

03 mitt

mitt它是一个第三方的库，作用很简单就是任意组件 <–> 任意组件之间传输，要使用它我们得先下载与配置

<script lang="ts">
//配置mitt
// 1.在当前目录的终端下输入 npm i mitt
// 2.在src中新建一个文件夹和文件叫utils/emitter.ts
// 3.在emitter.ts中键入以下代码来进行基础配置
import mitt from 'mitt'

// 4.!调用mitt获得mitter，这样就可以绑定事件 和 触发事件
const emitter = mitt()

// 5.基础用法，绑定事件、触发事件、解绑事件
//1.绑定事件「on」
emitter.on('test', () => { //解析：绑定了一个叫test的事件，它后面可以被触发等操作
  console.log('test被调用了');
})

//2.触发事件「emit」
// emitter.emit('test') 直接触发
setInterval(() => {
  emitter.emit('test') //解析：这里定时器1秒后触发 test事件里面的内容
}, 1000); //计时器触发

//3.解绑事件off/all
setTimeout(() => { //解析：把test事件给解除绑定，不在触发它
  //单独解绑
  emitter.off('test')
  console.log('test被解绑了');
  //解绑所有
  emitter.all.clear()
}, 3000);
  
  //!!! 这里一定要把mitt给暴露出去，不然外部组件查无此人 !!!
  export default mitt()
</script>

上面的代码看明白了的，就可以知道mitt怎么写了，其实很简单它和emit很相似，只不过会用到emitter.on/emit/off这类，下面我就简单一下二个组件之间怎么使用mitt来进行传输，这里说一个公式就是 数据在谁手里谁就是emit，接收数据的就是on

这里的off有一个很重要的点，如果有二个组件都on('data',...)那么其中一个写off('data')就会把二个on全部解绑，这很危险⚠️

//组件1
<template>
	<!-- 这里的send是名称，接收方也要使用这个-->
	<button @click="emitter.emit('send',data)">点击将数据data传输给组件2</button>
</template>
<script setup lang="ts">
  //记得引入刚才配置好的emitter
  import emitter from './utils/emitter.ts'
  import {ref} from 'vue'
  const data = ref('Book')
</script>



//组件2
<template>
	<h3>组件1发送过来的数据是：{{ js }}</h3>
</template>
<script setup lang="ts">
  import emitter from './utils/emitter.ts'
	import {ref,onUnmounted} from 'vue'
  //定义一个响应式数据来接收发送方的数据
  const js = ref('')
  
  //第一个是名称，第二个是函数
  emitter.on('send',(book:string)=>{
    js.value = book
  })
  
  
  //注意！
  //在该组件卸载（也就是删除这个页面后）后一定解绑getToy事件,不然后续还可能会调用到它，对内存不好
  onUnmounted(()=>{
    emitter.off('send')
    console.log('send被解绑了');
  })
</script>

04 v-model

来到v-model，这次有二个标签的用法，我会一一说明的，首先讲一下v-model是什么，它其实就是用在input标签上的一个双向绑定工具，效果就是当用户在input里输入内容时，input的内容会传递给变量，实现在 頁面 -- 數據 的双向绑定，页面的数据发生改变，数据本身也会发生改变，相互作用

//1.v-model用在普通标签上
<template>
	<!-- 将 响应式数据data 绑定到input标签-->
	<!-- 这里打开控制台可以尝试，修改input的数据，data也会发生改变 -->
	<input v-model.number="data"> <!-- 这里记得加.number,因为v-model在原生input上是字符串-->
</template>

<script lang="ts" setup>
	import {ref} from 'vue'
  const data = ref(1)
  
  //！在普通标签上的底层执行逻辑
  // 2.1：v-model的底层原理 :value就是其中一个线，@input就是另一条线  
  // 2.2：:value="data" = "输入框显示 data 的值"（数据 → 页面）
  // 2.3：@input="..." = "用户一打字，就把新值写回 data"（页面 → 数据）  
  // <input type="text" :value="data"@input="data = ($event.target as HTMLInputElement).value" 
  // 2.4：HTMLInputElement就是告诉TS这里一个HTMLinput类型的元素不可能为空 
</script>
//2.v-model在自定义标签(input)上
//我们要先创建一个Zdy.vue文件，然后这个文件格式与普通vue一样，自定义标签就是在这个Zdy.vue里面写一个input标签并给它添加一些style作为样式，然后我们把这个Zdy.vue引入到主页面中，进行使用
<template>
	<!-- 使用自定义标签-->
	<!-- 这里和普通的input标签一样，主要是自己修改样式区别，这里我主要讲一下它和input不一样的底层原理-->
 	<Zdy v-model="user">
</template>

<script lang="ts" setup name="home">
	//引入Zdy.vue
  import Zdy from './Zdy.vue'
  import {ref} from 'vue'
  const user = ref('name')
  
  //！在自定义标签上的底层执行逻辑
 	// Zdy底层原理 :modelValue是接收数据 而@update:modelValue是一个方法名称，它们是自定义input默认约定名
  // <LyraInput :modelValue="username" @update:modelValue="username = $event"/> 
  
  // ！修改ModelValue 
  // 这里的加上:user和可以理解为别名，它代替了原本的:modelValue和@update:modelValue，起了后在Zdy.vue中的:value="ModelValue"改成user
  // 这里实现了一个自定义input，展示了二个input组件 
  // <LyraInput v-model:user="username"  /> 
</script>
//3.Zdy.vue文件的内容与样式（已经修改ModelValue）
<template>
    <!-- ！为什么这里的$event可以target而组件标签上不行呢？
    1.因为这里的input是HTML标签而且是DOM操作这里可以获取到当前点击事件的value
    2.而组件标签上的是$event没有target,它的意思就是事件触发时，传递过来的数据 -->
    <input type="text"
     :value="user" 
     @input="emit('update:user',(<HTMLInputElement>$event.target).value)"
    >
</template>

<script lang="ts" setup name="Zdy">
    defineProps(['user'])
    const emit = defineEmits(['update:user'])
</script>

05 $attrs

接着，我们要了解$attrs，它的作用就是 父组件传给子组件的数据 但子组件没有接收的数据存储进去，这个数据可以给孙组件，作用和用法都很简单，我用三个代码块来讲解

//1.父组件
<template>
		<!-- 使用v-bind(:)把变量传递过去-->
		<Childen :toy="toy" :bag="bag" />
</template>
<script lang="ts" setup name="Father">
  //1.引入子组件
  import Childen from './Childen'
  import {ref,reactive} from 'vue'
  //2.定义一些数据，然后传递给子组件
  const toy = ref('LEGO')
  const bag = reactive({
    pen:'1',
    book:'5',
    tools:'1'
  })
</script>
//2.子组件
<template>
		<h4>BAG:{{ bag }}</h4>
		<!-- 这里就是把父组件给的数据，但子组件没有使用 那他们就存在了$attrs里面，把$attrs再传给孙组件 那边就可以使用了 -->
		<!-- 打开控制台查看$props(子使用的数据会在这里展示) $attrs(这里存的是子没有使用的数据)-->
		<!-- 这里还需要把孙组件引入并给它绑定v-bind="$attrs"里面的变量$attrs就是子组件没有使用的数据-->
		<GrandChild v-bind="$attrs" />
</template>
<script lang="ts" setup name="Childe">
	//引入孙组件
  import GrandChild from './GrandChild'
  defineProps(['bag']) //用了bag,$attrs这没有了
</script>
//1.孙组件
<template>
	<h3>子组件没使用的数据：{{ toy }}</h3>
</template>
<script lang="ts" setup name="GrandChilde">
	//孙组件这里要用Props来接收子组件没有使用的数据
  defineProps(['toy'])
</script>

06 $refs / $parent（实例直接访问，了解即可，不推荐常规通信）

说明：属于直接拿到组件实例的通信方式，耦合高，业务尽量优先 props + emit，仅特殊场景使用

$refs（父组件访问子组件 / DOM）

父组件给子标签绑定 ref，获取子组件实例。子组件需要用 defineExpose 主动暴露变量、方法，父组件才能拿到。多用于调用子组件方法（表单校验、弹窗开关），不适合做数据同步

<!-- 子组件 -->
<template>
  <h1>子组件</h1>
</template>
<script setup lang="ts">
import { ref } from 'vue'
const msg = ref('子里面的消息')
// 向外暴露内容，父$refs才能访问，也就是把自己想要父可以改动的数据暴露出去，父才可以动子的东西
defineExpose({ msg })
</script>

<!-- 父组件 -->
<template>
  <Child ref="childRef" />
  <button @click="getSon">访问子组件</button>
</template>
<script setup lang="ts">
import { ref, onMounted } from 'vue'
import Child from './Child.vue'
const childRef = ref<InstanceType<typeof Child>>()

const getSon = () => {
  console.log(childRef.value?.msg)
}
// 注意：必须挂载完成后 $refs 才有值
onMounted(() => {
  console.log(childRef.value)
})
</script>

$parent（子组件访问父组件实例）

子组件通过 $parent 直接拿到父实例，读取 / 修改父的数据。耦合极强，层级一变直接失效，官方不推荐，优先改用自定义事件 emit

//子组件 
<template>
  <h1>子组件</h1>
	<!-- ！这里很危险，子这边不需要引入什么，父那边也不需要写什么，但子就可以随便控制父里面的数据，所以不推荐使用-->
	<!-- 重申：这里看补充-->
  <button @click="$parent.num++">直接修改父的数据（不推荐）</button> 
</template>
<script setup lang="ts">
// 不需要导入，模板内直接使用 $parent
</script>


//父组件
<template>
  <h1>父组件数据：{{ num }}</h1>
  <Child />
</template>
<script setup lang="ts">
import { ref } from 'vue'
import Child from './Child.vue'
const num = ref(100)
</script>

补充：默认全封闭。父想拿子的东西，子必须 defineExpose。子想拿父的东西，父也必须有暴露（而 <script setup> 做不到），所以 $parent 在 <script setup> 组件之间基本是死的。

07 provide / inject

接下来这个与之前的$attrs有一点点相似之处，provide/inject 它们的作用就是让 父组件可以直接传数据给孙数据，且不需要子组件的参与

而$attrs它是需要子组件作为中转的，而且子组件还要引入和写东西，孙组件才能使用，provide/inject就完美解决了这个问题，它不需要子组件过多的参与就可以让 ‘爷孙’ 直接进行数据的传输（但是我们还是需要要它）

provide/inject 的前提：组件必须处在「祖先 — 后代组件树关系里」，不是凭空跨组件传值。祖先依然要渲染中间那一层子组件，只是【传数据不用经过中间组件手动转发】

//父组件
<template>
	<h1>父</h1>
	<Childen />
</template>

<script lang="ts" setup name="Father">
  	//这里要引入子组件才能实现给孙组件传数据，因为不能凭空给一个传输数据
  	import Childen from './Childen'
  	import { ref,provide,reactive } from 'vue'
  	//定义一些数据
  	const money = ref(5)
    const car = reactive({
    brand:'BMW',
    price:'100'
  })
  function updateMoney(value:number) {
    money.value -= value
  }
  //使用provide进行传递，它是一个函数 (记得在vue中引入provide)
  //provide('数据名',数据)
  provide('money',{money,updateMoney}) //使用{}可以传递多个
  provide('car',car)
 	//这里主要演示祖传孙（父传子也可以的）)
</script>



//子组件
<template>
		<h2>子</h2>
		<GrandChilden />
</template>

<script lang="ts" setup name="Childen">
  	//引入孙组件这样它们才有关系
  	import GrandChilden from './GrandChilden'
</script>



//孙组件
<template>
    <h4>银子：{{ money }}</h4>
    <h4>车子：品牌{{ car.brand }}，价格{{ car.price }}</h4>
    <button @click="updateMoney(1)">点我祖组件money减1</button>
</template>

<script lang="ts" setup name="GrandChilden">
  import {inject,ref} from 'vue'
  //填传过来的名称
  //2.孙组件这里要把祖组件的数据解构出来
  
  //写一个TS规范
  type MoneyCtx = { money: Ref<number>; updateMoney: (v: number) => void }
  //新const { money, updateMoney } = inject<MoneyCtx>('money', { money: ref(0), updateMoney: () => {} })!
  
  let {money,updateMoney}:any = inject('money',{money:0,updateMoney:(x:number)=>{}})
  let car = inject('car',{brand:'未知',price:0}) //这里设定一下规则就是没有数据就让brand和price为0，这样就可以消除	TS的规定
  //inject('名称','默认值')
  //默认值是数据没有传过来时会显示的默认数据
</script>

08 Pinia基础

pinia它也是官方维护的一个API，但需要单独下载，它的作用是数据共享，任意组件 <–> 任意组件 之间进行共享数据或状态，可以把pinia想象成一栋大楼，里面有很多房间(store)，每个数据都有自己专属的房间(store)，每个房间都存放着一类数据，相同组件可以一起使用这个房间(store)，这就是pinia的基本概念，想要使用pinia还是要先安装，然后在main.ts里面配置好，如下

//一、安装pinia，在当前Vue项目终端中，输入npm i pinia
//二、安装完成后，我们在main.ts，进行相关配置
------ main.ts ------
<script>
import { createApp } from 'vue'
import App from './App.vue'
// 1.引入pinia
import { createPinia } from 'pinia'
let app = createApp(App)
// 2.创建pinia
let pinia = createPinia()
// 3.安装pinia
app.use(pinia)
app.mount('#app')
</script>
------ main.ts ------
//三、创建一个文件夹，名为store，里面要存放组件专属数据（记得创建组件文件夹components）

上面的基本工作完成后，现在分别在components创建「Count.vue」和store创建「Count.ts」名称是一样但是后缀和路径不一样，要注意，接下来我们先在主页面(app.vue)中引入并显示这两个组件

//下面为app.vue中的内容，要让页面显示这两个组件
<template>
    <div>
        <Count />
    </div>
</template>

<script lang="ts" setup>
defineOptions({ name: 'app' })
import Count from './components/Count.vue';
</script>

先写Count.ts

// Count.ts
<script>
//1.在pinia身上拿到 defineStore ，它就是「房间」
import { defineStore } from "pinia";

//2.这里命名推荐使用官方建议的hooks命名 useXxxStore
//defineStore参数有两个，第一个是id值，最好和ts文件名一致，它是区分其它store方法，所以不能重名
//第二个是配置对象
//defineStore其实和Vue2的格式基本一致
export let useCountStore = defineStore('Count', {
  
    // state存储数据的地方
    state() {
        return {
            sum: 8,
         		school: 'NSCU',
            address: '四川泸州'
        }
    },
  
   	// actions用于存储数据的'动作'，也就是函数/方法
    actions: {
        increment(value: any) {
            //这个this就是当前的Store（useCountStore）
            this.sum += value

        }
    },
    
      // getters相当于计算属性
    getters: {
        //第一种写法，匿名函数
        //可以直接拿到state的数据
        BigSum: (state) => state.sum * 10,

        //第二种写法，普通函数式
        muSgiB(): string { //这里有TS的检测，意思是你return东西必须指明它是一个什么类型
            //不用匿名函数的时候可以用this(useCountStore)来取代state
            return this.school.toUpperCase()
        }

    }
}) 
</script>

然后我们在写Count.vue

<template>
    <div class="count">
        <!-- 这里有了pinia专为Count准备的仓库后，这个仓库里面的数据可能以后不止Count.vue使用 -->

09 插槽（默认 / 具名 / 作用域）

插槽它也是一种 父 --> 子 的类型，只不过从数据，变成了结构相关的，这里说一下父的作用：父就是存放子的标签以及标签里面的HTML代码等，子的作用：使用插槽可以指定 父那边的内容 在子的哪个位置，这么说可能比较模糊，接下来用二个代码块来讲清楚三种插槽的作用，以及它们的特点，因为默认和具名可以一起说

//默认插槽
//父组件
<template>
  <div class="father">
    <h3>父组件</h3>
    <div class="box">
    <!-- 1.这里可以用双标签，和单标签一样可以正常显示，双标签可以在里面插入内容，但是一开始是不会有显示的 -->
    <!-- 2.原理是Vue知道你要在子组件里显示这个内容，但是你的子组件并没有 
    提示放在什么地方，就会导致它干脆就不放了，想要在内加内容并让子组件也显示
    需要在子组件那里声明soltE插槽，它就知道要显示在哪个位置了-->
    <Category>
